# C4

## Qué es y cuándo usarla {#que-es}

El modelo C4, de Simon Brown, describe la arquitectura de un **software** con cuatro niveles de zoom,
como un mapa: el **contexto** (el sistema y quién lo usa), los **contenedores** (las aplicaciones y bases
de datos que lo forman), los **componentes** de cada contenedor y, si hace falta, el **código**. Añade
una quinta vista de **despliegue** (en qué servidores corre cada cosa).

Úsala para explicar un sistema a un equipo nuevo, preparar una revisión de arquitectura o documentar
qué habla con qué. Es más sencilla que ArchiMate y se entiende sin formación previa. Si necesitas
relacionar el software con procesos de negocio, enlázala con [ArchiMate](archimate.md).

## Elementos clave {#elementos-clave}

| Elemento | Nivel | Qué representa |
|---|---|---|
| **Persona** | Contexto | Un usuario humano: "Gestor comercial", "Cliente" |
| **Sistema de software** | 1 · Contexto | Algo que entrega valor por sí mismo: "CRM". Contiene contenedores |
| **Contenedor** | 2 · Contenedor | Una aplicación o almacén que se despliega por separado: "Portal del gestor", "API de clientes", "Base de datos". Campos **Tecnología** y **Clase** (app, base de datos, cola, navegador, móvil, microservicio…) |
| **Componente** | 3 · Componente | Una pieza de un contenedor con una interfaz clara |
| **Código** | 4 · Código | Una clase, interfaz o módulo (nivel opcional) |
| **Nodo de despliegue** | Despliegue | Infraestructura: servidor, máquina virtual, clúster, servicio cloud. Se anidan y tienen **Instancias** |
| **Límite** | Cualquiera | Un marco discontinuo para agrupar (empresa, sistema, grupo) |

Personas y sistemas tienen el campo **Externo**: márcalo para lo que está fuera de tu alcance y se
pintará en gris, como manda C4.

## Relaciones {#relaciones}

| Relación | Para qué |
|---|---|
| **Relación** | La relación genérica de C4. Rellena la **Descripción** ("Lee y escribe") y la **Tecnología** ("JSON/HTTPS", "SQL"). Es la relación por defecto |
| **Usa** | Igual que la anterior pero con el verbo explícito "el origen usa al destino"; útil al exportar a Structurizr |

## Cómo empezar {#como-empezar}

Así se construye la vista *CRM · Contenedores* de la demo:

1. En el panel **Vistas**, pulsa **＋** y elige **C4**. En el inspector de la vista, elige el viewpoint
   **Contenedor**.
2. Arrastra un **Sistema de software** "CRM" y hazlo grande: será el marco que contiene al resto.
3. Arrastra **dentro** del sistema tres **Contenedor**: "Portal del gestor" (Tecnología *React*, Clase
   *browser*), "API de clientes" (*Node.js*, *microservice*) y "Base de datos" (*Postgres*, *database*).
4. Fuera del sistema, añade otro **Sistema de software** "Proveedor KYC" y marca **Externo**.
5. Une portal → API ("JSON/HTTPS"), API → base de datos ("SQL") y API → proveedor KYC ("REST") con
   **Relación**.
6. Para que el CRM de ArchiMate abra esta vista con doble clic, ve a la vista ArchiMate, botón derecho
   sobre "CRM" → **Abrir en otra dimensión** o elige esta vista en **Vista al hacer doble clic** del
   inspector.

## Reglas de la notación {#reglas}

- **Jerarquía por anidamiento**: un sistema contiene contenedores, un contenedor contiene componentes y
  un componente contiene código. Un nodo de despliegue contiene otros nodos y contenedores; un límite,
  cualquier cosa. Anidar no crea ninguna relación.
- **Matriz**: casi todo puede relacionarse con casi todo, salvo dos excepciones: una persona no se
  relaciona con otra persona, y el **Código** solo se relaciona con código o componentes.
- **Viewpoints = niveles**: *Contexto* (personas, sistemas, límites), *Contenedor* (añade contenedores),
  *Componente* (añade componentes), *Código* (añade código) y *Despliegue* (nodos, contenedores y
  sistemas). Lo que no pertenece al nivel sale atenuado en la paleta.

## Importar y exportar {#importar-exportar}

- **Structurizr JSON**: importa y exporta personas, sistemas, contenedores, componentes, despliegue,
  relaciones y vistas con posiciones. Al exportar se omiten, con aviso, los límites y el nivel de código.
  Ver la [tabla de formatos](../importar-exportar.md#formatos).
- Cada vista también se exporta a SVG, PNG, Mermaid y draw.io.

## Errores comunes {#errores-comunes}

- **Mezclar niveles en una vista**: un diagrama de contexto con contenedores sueltos confunde. Usa una
  vista por nivel y enlázalas con vistas de detalle.
- **Relaciones sin descripción**: una flecha sin "qué" ni "cómo" no explica nada. Rellena siempre
  **Descripción** y **Tecnología**.
- **Contenedor ≠ contenedor Docker**: en C4 un contenedor es cualquier cosa que se despliega por
  separado (una web, una API, una base de datos). Los contenedores Docker o los servidores son **Nodos
  de despliegue**.
- **Dejar los contenedores fuera del sistema**: si no los anidas dentro de su sistema, el exportador a
  Structurizr los pone en "Sin sistema".
